01The big idea · Slides 3–8

The city with one giant building

📖 Chapter one

Mira owns a giant building, but five companies want their own offices. Building five separate skyscrapers would waste money. So she divides one building into secure offices, each with its own doors, desks, and rules. One physical building, many independent spaces. That is the idea behind virtualization.

Virtualization divides a physical computer's resources—processor, memory, storage, and network—into several virtual resources. Different users can share the same hardware; this is called multi-tenancy.

02The manager · Slides 9–14

Meet the building manager: the hypervisor

📖 Chapter two

Teams begin moving into Mira's building. Someone must decide who gets how much electricity, space, and security. Mira hires a manager named Hyper. Hyper makes sure each team gets resources and doesn't interfere with its neighbors.

A hypervisor (also called a Virtual Machine Monitor / VMM) is software that lets multiple operating systems share one hardware host. It controls resource allocation and keeps virtual machines isolated. A VM is a self-contained computing environment that feels like a complete computer, although it uses only part of the physical host.

03Two ways to run the city · Slides 15–17

Full vs. para-virtualization

📖 Chapter three

Hyper offers two styles of service. In the first, tenants act as if their office is an entire independent building. In the second, tenants know they're sharing and can directly ask the manager for help.

🎭

Full virtualization

“I think this is my own computer.”

The guest OS is unaware it is virtualized. The hypervisor provides a virtual hardware environment, using emulation, binary translation, or hardware assistance.

  • Guest OS need not be modified
  • Supports multiple operating systems
  • May have extra overhead

Lecture examples: VMware ESXi, Microsoft Hyper-V, Oracle VM VirtualBox.

🤝

Para-virtualization

“I know I'm virtual; I'll ask directly.”

The guest OS cooperates with the hypervisor using special requests called hypercalls.

  • Can reduce overhead
  • Direct hypervisor communication
  • Requires a modified/cooperating guest OS in the classic model

Lecture example: Classic Xen.

04Where everything lives · Slides 18–25

The city's shared storage warehouse

📖 Chapter four

Mira's teams are saving thousands of files. Some disks are almost full while others are empty. She creates a central warehouse: several physical storage devices are presented as one organized storage pool. Teams receive their own virtual storage spaces without needing to know which physical disk holds each file.

Storage virtualization hides the identities of physical storage devices. A virtualization layer maps logical storage (what the VM sees) to physical storage (where the data really lives), creates a pool, and assigns virtual volumes to compute systems.

Easy memory trick: SAN is commonly about shared block-level storage; NAS provides shared file-level access. This distinction is an added learning aid, beyond the slides' wording.

VMFS: the warehouse's filing system

The lecture introduces VMFS (Virtual Machine File System) as a file system for storing and managing VM files. Multiple compute hosts can access a VMFS volume, and on-disk locking helps coordinate access. A virtual disk file represents a VM's disk; the VM need not know the underlying physical storage technology.
