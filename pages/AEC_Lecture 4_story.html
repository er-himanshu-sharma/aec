Cloud Providers & Scheduling explained like a simple story

Imagine your company QuickKart becomes popular. You need cloud infrastructure, development tools, monitoring and a smart way to decide which task should run on which server.

Chapter 1

🏢 Cloud Service Providers (CSP)

QuickKart needs servers, storage, networking, backup, monitoring and security. Instead of building a huge data centre, it uses a Cloud Service Provider.

Electricity analogy: You do not build your own power station. Similarly, you can consume computing resources from a cloud provider.
Cloud Provider
      ↓
Your Company
      ↓
Servers • Storage • Network • Security • Monitoring
🖥️

Massive Infrastructure

Large providers operate thousands of computers and servers.

🧩

Virtualization

Physical resources are exposed as flexible virtual resources.

🔌

Redundancy

Redundant power, networking and connectivity improve resilience.

Interesting point: A cloud-based service may itself use another provider's infrastructure.

Chapter 3

🔷 Microsoft Azure

The lecture presents Azure as an enterprise-level, on-demand capacity platform with compute and storage available on request for a cost.

Web Role

Think of it as handling web requests.

Worker Role

Think of it as background processing.

Blob Storage

Storage for large unstructured objects.

Memory: Web Role = web requests, Worker Role = background work, Blob = large files.
Chapter 4

🟧 Amazon EC2

EC2 is described as a large web service that can create computing instances through an API using supported operating systems.

Simple story: You say, “Amazon, I need a Linux machine.” EC2 creates a virtual machine instance for you.
Request
  ↓
Amazon EC2
  ↓
Virtual Machine Instance

AMI

Chocolate-mould analogy: AMI is like a reusable mould or template from which multiple similar instances can be created.

S3 and Load Balancing

S3

Think of it as Amazon storage for files and objects.

Load Balancing

Distributes incoming work so one server does not receive everything.

Easy memory: EC2 = Compute, S3 = Storage, AMI = Machine Template.

Most Important New Topic

⏱️ Scheduling in Cloud Computing

QuickKart now has 100 users, 1000 tasks and 20 servers. Someone must decide which task should run on which resource.

Restaurant analogy: If 50 orders arrive and you have 5 chefs, a manager must decide which chef gets which order. That manager is like a cloud scheduler.
✅

Task Scheduling

For independent tasks.

🔗

Workflow Scheduling

For dependent tasks.

🖥️

Resource Scheduling

Focuses on how resources should be used.

Static vs Dynamic

TypeEasy Meaning
StaticScheduling decisions are made before execution.
DynamicScheduling decisions can change while the system is running.

Preemptive vs Non-Preemptive

Preemptive

A running task can be paused so another task can run.

Non-Preemptive

Once a task starts, it continues until completion.

Workflow Scheduling

Food-delivery analogy: Take order → Cook → Pack → Deliver. These jobs depend on one another, so they form a workflow.

Resource Scheduling Goals

💰 Cost-Aware

Considers revenue, resource cost and user expenses.

⚡ Efficiency-Aware

Considers makespan, execution time, bandwidth and speed.

🌱 Energy-Aware

Considers energy consumption.

⚖️ Load-Balancing-Aware

Tries to distribute total workload.

🎯 QoS-Aware

Considers SLA, availability, fault tolerance and reliability.

📈 Utilization-Aware

Focuses on efficient resource utilization.

Important Terms

TermSimple Meaning
MakespanTotal time taken to finish all tasks.
QoSQuality of Service.
SLAService Level Agreement.
