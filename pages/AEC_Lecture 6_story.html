Chapter 1

🧪 What is CloudSim?

CloudSim is an open-source simulation toolkit used to model, simulate and evaluate cloud-computing environments.

Story: Before spending money on a real cloud data centre, imagine creating a “practice cloud” on your laptop. You can create virtual machines, submit tasks, try different scheduling ideas and observe what happens.
CloudSim = A laboratory for cloud experiments.

Chapter 3

🧮 The Four Calculations You Must Understand

1. Execution Time

Execution Time = Task Size (MI) ÷ VM Speed (MIPS)
Example: T1 has 7000 MI. On VM1 at 2000 MIPS: 7000 ÷ 2000 = 3.5 seconds.

2. Communication Time

Communication Time = (Input MB + Output MB) ÷ Bandwidth
Example: T1 has 200 MB input + 50 MB output. With 50 MB/s bandwidth: 250 ÷ 50 = 5.0 seconds.

3. Total Task Duration

Task Duration = Execution Time + Communication Time
For T1 on VM1: 3.5 + 5.0 = 8.5 seconds.

4. Makespan

Makespan = Maximum completion time among all VMs
Memory: The whole assignment is finished only when the busiest/last VM finishes.

Cost and Energy

Compute Cost = Σ(Execution Time × VM Cost/sec)
Data Cost = (Input + Output in MB) × (1/1024 GB/MB) × ₹0.02
Energy = Σ(Execution Time × VM Energy Rate)

Schedule C

🧲 Greedy Shortest-Execution-Time Scheduling

Rule: For every task, choose the VM where that task has the smallest execution time.

In the lecture's numbers, VM3 has the highest MIPS, so every task has its shortest execution time on VM3. Therefore the greedy assignment becomes the same as Schedule B.

Greedy Result in this problem
Same assignment as Schedule B → Makespan 35.6 s, Cost ₹11.5067578125, Energy 1804 J.
Chapter 5

⚖️ The Big Lesson — Fastest VM Does Not Always Mean Fastest Schedule

ScheduleIdeaMakespanTotal CostEnergy
Round RobinSpread tasks across VMs15.1 s₹12.02675781252133.4 J
All on VM3Use only fastest VM35.6 s₹11.50675781251804 J
Greedy shortest execPick fastest VM per task35.6 s₹11.50675781251804 J
Restaurant lesson: The fastest chef may cook every individual dish faster, but if every customer queues at that one chef while the other chefs sit idle, the entire restaurant can finish later.
Trade-off shown by this lecture:
Round Robin gives a much lower makespan because it uses parallel resources, while the all-on-VM3 schedule has lower cost and energy in the provided calculations.
