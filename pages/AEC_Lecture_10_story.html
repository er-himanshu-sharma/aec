Chapter 01 · Meet the team

Welcome to ByteTown 🏙️

Our story: Mira manages a tiny computing center. Customers have sent six jobs. Mira has only three virtual machines (VMs). Some are fast, some slow. Her mission is simple: finish all the jobs as early as possible.

📦 Tasks

Each task is a parcel of computing work. A bigger parcel takes longer to process.

🖥️ Virtual machines

Each VM is a worker. Faster workers complete the same task sooner.

⏱️ Makespan

The time when the last worker finishes. This is what Mira wants to minimize.

Remember: makespan is not the sum of all VM times. It is the maximum VM finishing time, because the VMs work in parallel.

Chapter 02 · Nature gives Mira an idea

Genetic Algorithm: survival of the better schedule 🧬

Instead of testing every possible arrangement manually, Mira borrows an idea from evolution: create several schedules, measure them, prefer better schedules, mix them, and occasionally make a small random change.

Chromosome

A schedule written as six numbers. [1 2 3 1 2 3] means tasks 1 and 4 go to VM1, tasks 2 and 5 to VM2, and tasks 3 and 6 to VM3.

Fitness

A score that rewards faster completion. In this lecture, fitness = 1 / makespan. Smaller makespan → larger fitness.

Evolution

Selection chooses parents; crossover combines their genes; mutation changes one gene. Then evaluate the new schedules again.

Lecture algorithm in plain English

Create the starting population of schedules.
Calculate fitness for each schedule.
Select parents, perform crossover, and mutate a gene.
Recalculate fitness; continue until a stopping condition is reached.

The slide's pseudocode uses “fitness value != optimal value”; practical implementations often stop at a target, a generation limit, or when improvement stalls.

🎡 Roulette-wheel selection

Imagine a prize wheel. Better schedules get larger slices, but even weaker schedules retain some chance. This encourages exploration rather than always picking the same winner.

Probabilities from the lecture (approximately): C1 23.8%, C2 21.8%, C3 26.2%, C4 28.1%. These are not guaranteed winners. The lecture illustrates selecting C4 and C3 as parents.

✂️ One-point crossover (after gene 3)

Cut each parent after its third gene and exchange the right-hand halves.

C4: [1 3 2 | 3 1 2]
C3: [3 1 2 | 2 1 3]
↓
O1: [1 3 2 | 2 1 3]
O2: [3 1 2 | 3 1 2]

🎲 Mutation: a tiny surprise

For offspring O1, change gene 5 from 1 to 3. That moves T5 from VM1 to VM3.

[1 3 2 2 1 3] → [1 3 2 2 3 3]

The lecture's new offspring are O1 = [1 3 2 2 3 3] and O2 = [3 1 2 3 1 2].

Important: a genetic algorithm does not promise improvement in every generation. Here the two offspring have makespans of 10.67 s and 12 s—both worse than the original C4 (9.33 s). Preserving C4 would require an extra strategy such as elitism, which the lecture does not specify.

Chapter 04 · Too much work for one worker

Load balancing: share the burden ⚖️

Our story: VM1 has a huge queue while VM2 is almost idle. Mira says, “Why should customers wait when another worker is free?” She redistributes tasks.

Load balancing spreads work across resources to improve utilization, reduce waiting time and makespan, support performance, stability, and resilience.

📋 Static balancing

Decide where work goes using a predefined plan, without relying on the system's changing state.

Example: assign jobs in a fixed rotation.

📡 Dynamic balancing

Observe system load and adapt decisions as conditions change.

Example: send the next job to a currently less-busy VM.

Chapter 05 · Moving house versus moving parcels

VM migration ≠ task migration 🚚

🏠 VM migration

Move the whole virtual machine—its operating environment and applications—from one physical host to another.

Story: Mira must repair Server A, so she moves its VM to Server B to keep the service available.

📦 Task migration

Move selected tasks from an overloaded VM to an underloaded VM, leaving the original VM in place.

Story: Mira shifts two waiting jobs from VM1 to VM2 instead of moving the whole worker.

Five decisions before moving a task

Information policy: What load data should we collect, and when?
Triggering policy: When should rebalancing start?
Resource type policy: Which resource is overloaded (sender) and which has capacity (receiver)?
Location policy: Which suitable receiver should be chosen?
Selection policy: Which particular tasks should move?

Memory trick: Information → Trigger → Sender/receiver → Location → Task selection.

Chapter 06 · One building, many apartments

Virtualization: one physical machine, many virtual ones 🏢

Our story: Mira owns one powerful physical server. Rather than give the entire server to one customer, she partitions its resources so several customers can run their own virtual machines. Think of one building divided into independent apartments.

Virtualization divides physical computing, memory, storage, and network resources into virtual resources. Multi-tenancy means multiple users can share the same physical infrastructure while using logically separated environments.

How the lecture's architecture fits together

Simplified recreation of the hosted architecture shown on slide 22: server hardware → host OS → hypervisor → multiple VMs, each with a guest OS, libraries and applications. Other hypervisor architectures exist, but this matches the lecture diagram.

🧱 Hardware

The real CPU, memory, storage, and network devices.

🧑‍✈️ Hypervisor

The virtualization layer that creates and manages VMs and allocates hardware resources.

🪟 Guest OS

An operating system inside a VM. It can differ from the host operating system.

Six types shown in the lecture

📱 Application

Make applications run in a virtualized or isolated application environment.

🌐 Network

Create logical networks on top of physical network hardware.

🖥️ Desktop

Provide virtual desktop environments to users.

💾 Storage

Combine or abstract storage devices into logical storage pools.

🗄️ Server

Run multiple virtual servers on one physical server.

🧩 Data

Present data from different sources through a unified virtual view.

The lecture names these six categories on slide 24; the one-sentence examples above are added as teaching explanations.
